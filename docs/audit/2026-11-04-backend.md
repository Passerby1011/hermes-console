## 3. 高优先级

### H1 模块开关是元数据，不是访问边界

**现象**：`dashboard/plugin_api.py:50-54` 把 15 个域模块名写死在 `DOMAIN_MODULES`，第 90-98 行逐个 `include_router`，没有任何条件分支。整条挂载路径不读 `dashboard/modules/*/manifest.json`，也不消费 `core.registry` 算出的启用集。

**证据链**

1. `dashboard/core/registry.py:6-8` 承诺「删掉目录 = 该模块下线」；`ModuleSpec.api_module`（第 84 行）只序列化给前端，从未参与导入或挂载。
2. `GET /modules?agent=X` 返回 `enabled: false` 时对应路由依然可访问——代码里不存在「按 enabled 跳过 mount」的路径。
3. `dashboard/modules/README.md:4` 的「删掉目录 = 该模块下线，不需要改 plugin_api.py」因此不成立；同文件第 91-94 行其实已承认「两套结构并行」。
4. 7 个薄封装 `modules/{advisor,agents,autogroup,lanes,overview,upgrade,weather}/api.py` 从未被 import，是死代码。

**影响**：给某 agent 关掉 `models` / `upgrade` / `vcc`，只让它从导航消失；HTTP 仍能改真实 `config.yaml`、起停对外 `hermes serve`、改 cron 状态。这是权限模型缺口，不是 UI 瑕疵。

**建议**（二选一，别维持现状）

- (a) 正确实现：`plugin_api` 用 `registry.enabled_modules(agent)` 决定挂载/放行；路由只挂一次，鉴权按请求解析 agent，disabled 返回 404/403。
- (b) 显式降级：把开关定义为「仅导航」，在每个写端点做 agent 级 enabled 检查，并改掉 README 的「下线」承诺。

推荐 (a)：registry 已具备全部信息，缺的只是接线。

### H2 manifest 默认值与文档策略相反

**现象**：12 个 `manifest.json` 全部 `default_enabled: true`，包括 `models`、`autogroup`、`advisor`、`upgrade`、`vcc`、`remote` 这些带写操作的模块。

**证据**

- `dashboard/modules/{models,autogroup,advisor,upgrade,vcc,remote}/manifest.json` → `default_enabled: true`。
- `dashboard/modules/README.md:79-89` 表格把这 6 个标为「**关**」，第 101 行写「纯只读默认开，带写操作默认关」。
- `STATUS.md:65-72` 已把 `probe_models.py` / `probe_registry.py` 的这组断言登记为「本卡之前就红」的已知遗留。

**影响**：新环境默认就具备全部写权限面；与 H1 叠加后，「UI 上默认不显示」这层缓解也只是表象。两支探针长期红灯，还会训练团队忽略红色信号。

**建议**：manifest 改 `false` 并补断言「带写模块必须 `default_enabled=false`」；或明确否决该策略，同步改文档与探针期望。任选其一，不要双标准。

### H3 AI apply/undo 域缺失，而文档、测试、探针仍按「已交付」描述

**现象**：以下 6 个模块文件均不存在：`api_autogroup_ai_apply.py`、`api_autogroup_ai_undo.py`、`api_autogroup_ai_run.py`、`autogroup_ai_contract.py`、`autogroup_ai_projects.py`、`autogroup_ai_store.py`。

**证据**

- 4 个测试模块 import 期即失败（`ModuleNotFoundError: api_autogroup_ai_apply`）：`tests/test_autogroup_ai_apply.py:26`、`tests/test_autogroup_ai_integration.py:38`、`tests/test_autogroup_ai_run.py:27`、`tests/test_autogroup_kanban_gates.py:30`。
- `tests/probe_ai_routes.py:40-45` 断言聚合内应有 10 条 `/autogroup/ai/*` 路由；实际 0 条。
- `AI_PREVIEW_CONTRACT.md:3-4` 把 `api_autogroup_ai_apply.py` / `api_autogroup_ai_undo.py` / `autogroup_ai_contract.py` 当现存实现来描述契约。
- 前端 `src/sections/autogroup-ai.js` 的注释则说明这些路由被有意删除。
- `autogroup_ai_projects` 还被 `test_autogroup_project_ops.py:168` 引用，是 51 条失败的根因之一。

**影响**：`pytest dashboard` 在收集阶段就中断，整库无法表达任何测试信号；契约文档与代码分叉，接手的人会按文档调用不存在的端点。

**建议**：先定方向。已废弃 ⇒ 删 4 个测试、`probe_ai_routes.py`、`AI_PREVIEW_CONTRACT.md`，README 记删除原因；保留 ⇒ 补齐 6 个模块。不允许「文档说有、代码没有、测试假装有」长期共存。

### H4 `_agent_secret` 跨 profile 取凭据

**现象**（`dashboard/api_models.py:1269-1282`）

```python
value = str(get_env_value_prefer_dotenv(name) or ")
if value:
    return value
return str(_env_map_for(agent).get(name) or ")
```

`get_env_value_prefer_dotenv` 按**当前进程 / 根 profile** 的 `.env` 解析，完全忽略入参 `agent`；只有取不到时才退回 `_env_map_for(agent)`（后者才正确叠加了该 agent 的 `.env`）。

**影响**：`base_url` 由 `_env_map_for(agent)` 解析（第 1285-1300 行），凭据却可能来自根 profile。对非 default agent 的探活/列举会把**根 profile 的密钥**发到**该 agent 的 base_url**：既可能泄露凭据，也会把「key 无效」误判成 provider 故障。

**建议**：把 `_env_map_for(agent).get(name)` 提到前面；或先进入 `_config_profile_scope(agent)` 再调官方取值器。补一条回归测试：非 default agent 只允许命中自身 `.env`。

## 4. 中优先级

### M1 请求校验错误绕过统一错误契约

实测（`plugin_api.router` 挂进 `FastAPI()` 后 `TestClient`）：

```
GET /vcc/conversations?agent=default&limit=abc
→ 422 detail: [{type: int_parsing, loc: [query, limit], msg: Input should be a valid integer ...}]
```

不是项目统一的 `{ok:false, error:{code,message}}`。凡用 FastAPI 类型化 `Query` / Pydantic `Body` 的端点都有此问题（`limit: int`、必填 body 缺失、枚举越界）。`api_console_settings.py` 手工解析参数以规避 422，说明团队已局部意识到，但没有全局方案。

**建议**：注册 `RequestValidationError` 处理器，转成 `{ok:false,error:{code:invalid_request,message,fields}}`；前端只需一套解析逻辑。

### M2 测试不 hermetic，本 worktree 不可能全绿

实测 297 collected / 139 failed / 77 passed / 1 skipped / 80 errors。按文件分布（前 10）：

| 文件 | 失败/错误数 |
| --- | --- |
| `test_autogroup_project_ops.py` | 51 |
| `test_api_autotitler.py` | 37 |
| `test_autogroup_consistency.py` | 23 |
| `test_autogroup_modes.py` | 23 |
| `test_api_advisor_coverage.py` | 16 |
| `test_api_advisor_injection_toggle.py` | 15 |
| `test_autogroup_ai.py` | 13 |
| `test_api_advisor_coverage_actions.py` | 12 |
| `test_api_advisor_profiles.py` | 8 |
| `test_autogroup_profile_scope.py` | 8 |

根因抽样：

- `FileNotFoundError: 找不到 hermes-auto-group/core.py：...\.worktrees\hermes-auto-group\core.py`（`api_autogroup.py:71`）→ autogroup 系全挂。
- `api_advisor.AdvisorUnavailable: 找不到 advisor 台账模块：...\.worktrees\advisor\audit.py` → advisor 系全挂。
- `test_api_autotitler.py` 复制 `PLUGIN_ROOT.parent / hermes-auto-titler`，worktree 下解析到不存在的目录。
- `dashboard/tests/ai_sandbox.py:33-38` 由 `__file__` 推算 `PLUGIN_ROOT`，指向 worktree 父目录，而兄弟插件不在那里。

**影响**：测试结果依赖「检出目录旁边恰好有 4 个兄弟插件」。干净 clone 上 CI 必红，开发者无法用测试判断回归。

**建议**：以显式环境变量（如 `HERMES_PLUGINS_ROOT`）指向 fixture 假插件，每个测试模块自带最小 `core.py` / `audit.py` stub；禁止从 `__file__` 向上猜兄弟目录。

### M3 `GET /upgrade/readiness` 有写副作用

`api_upgrade.py:450-469`：`_readiness_payload(..., allow_auto_restore=True)` 在存在待恢复快照时会恢复 cron 任务并写状态；第 521 行 `/readiness` 传的正是 `True`。而第 502-503 行 `/scan` 显式传 `False`，并在注释里写明「GET 不许产生写副作用」。

**影响**：同一次 GET 在不同时刻结果不同；预取、健康检查、浏览器重试都可能触发恢复。语义上应拆成只读 `GET /upgrade/readiness` + 显式 `POST /upgrade/restore`。

### M4 危险写端点的确认门不一致

已具备服务端 `confirm is True` 的：`/models/apply`、`/models/rollback`、`/models/batch`、`/vcc/engine`、`/autogroup/apply`、`/autogroup/undo`、`/autogroup/projects/*`、`/advisor/coverage/action`、`/remote/credentials/reveal`。

缺失的：`POST /remote/agent/start`、`POST /remote/agent/stop`（会真起/停对外 `hermes serve`）、`POST /upgrade/prepare`、`POST /upgrade/restore`、`POST /upgrade/kill`——这些只有 UI 侧确认或 `dry_run` 软约束。同一项目两套标准，后来者容易照抄错的邻近端点。

**建议**：抽出 `require_confirm` 依赖，对所有 destructive 路由强制 `confirm=true`，缺失则 400 `confirmation_required`。

### M5 错误体与成功体重复实现、语义不一致

至少 14 个 `_fail` / `_error_response` / `ApiError` 变体，签名与默认状态码互不相同：

- `api_agents_admin._fail(code, message, status_code=200)`——错误却默认 200；
- `api_autogroup._fail(code, message, status_code=400)`；
- `api_models._fail(status, code, message)`——参数顺序与别处相反。

成功体也有 `{ok, data}`、裸 `{ok, ...}`、`{ok, data, notes}` 三类，前端需逐域适配。

**建议**：`dashboard/core/` 提供唯一的 `ok()` / `fail()`，域模块只允许调用它；加一条测试断言「所有响应都含 `ok` 字段」。

### M6 home 解析 9 处重复、规则不同

`core.scope.hermes_home`、`api_agents.hermes_home`、`api_overview._hermes_home`、`api_upgrade.hermes_home`、`api_vcc._home`、`api_remote._home`、`api_advisor._home`、`api_lanes.hermes_home`、`api_models._home`。

差异点：`api_lanes` 认 `HERMES_HOME`，`api_upgrade` / `api_vcc` 不认。环境变量与默认路径不一致时，不同分区会读写不同的库。

**建议**：全部收敛到 `core.scope.hermes_home`，其余删除或改为薄别名。

### M7 兄弟插件运行时依赖未声明、也不进 health

- `api_autogroup._load_core()` 硬依赖 `../hermes-auto-group/core.py`；
- `api_autotitler` 读 `../hermes-auto-titler/plugin.yaml`；
- `api_advisor` 加载 `../advisor/audit.py`；
- `api_vcc` 读 `../hermes-vcc-cn/plugin.yaml`。

各 manifest 的 `requires` 只写本插件的模块 id，不表达「需要哪个兄弟插件」；`GET /health` 只反映 `dashboard/` 内部模块能否 import。兄弟插件缺失时域模块照样「加载成功」，错误推迟到首次请求（或测试 fixture）。

**建议**：manifest 增加 `plugin_requires`，`core.registry.health()` 做存在性探测并把缺失项放进 `failed`（带原因），前端据此禁用对应分区而不是报 500。

## 5. 低优先级与一致性

- **L1 文档与探针路由数过期**：`scripts/probe_console_settings_api.py:307`、`scripts/probe_plugin_catalog.py:362-364` 断言 71 条；`scripts/probe_registry.py:68` 的 `BASELINE_ROUTES` 同样陈旧。实际 121 条。`README.md:43` 写 `api_advisor` 7 路由（实际 11）；`modules/README.md:83-89` 写 models 13 / vcc 6 / remote 5 / advisor 7 / overview 6（实际 23 / 8 / 6 / 11 / 9）。
- **L2 `plugin_api.py` 文档字符串过期**：第 10 行「import 四个域模块」（实际 15），第 13-28 行表格只列 8 个域，第 30 行「40 个路由挤一个文件」（这个文件现在也只做聚合，但仍过时）。
- **L3 死代码**：`modules/*/api.py` 7 个薄封装从未被 import（见 H1）。
- **L4 `_rename_project` 非原子**：`api_autogroup_panel._rename_project` 依次写 `projects.db`、归属表、规则、台账，无跨库事务、无 undo 台账；中途失败留下悬空 slug 引用。
- **L5 端口未校验**：`/remote/agent/start` 接受任意整数 `port`，应限制 1..65535，并对「已被占用」给出结构化错误。
- **L6 无请求体上限**：`PUT /overview/layout` 等接受无界 JSON；本地服务风险有限，但布局写盘会被放大成磁盘放大面。
- **L7 卸载未防符号链接**：`api_advisor.coverage_action` 用 `shutil.rmtree(<profile>/plugins/advisor)` 卸载，profile 名已校验，但未对 symlink/junction 做 `realpath` containment 校验。
- **L8 upgrade 状态 fail-open**：`api_upgrade._load_state` 遇损坏文件返回 `{jobs: [], restored: true}`，静默丢弃待恢复快照（注释已把它写成刻意取舍；至少应记一条 `state_corrupt` 事件并暴露到 `/health`）。
- **L9 注释与实现不符**：`api_models.py:1174` 说缓存「只缓存成功」，实际失败结果也按 `LIVE_FAIL_TTL_SECONDS` 缓存（后文注释才是对的）。

## 7. 已核验通过的安全基线

- 无 bare `except:`；无 `eval` / `exec` / `os.system` / `shell=True`；`subprocess` 全部列表参数，无字符串拼命令。
- SQL 基本参数化；动态拼接仅限列名与控制流常量。
- 路径穿越：`api_models._resolve_snapshot` 强制快照根；`api_console_settings` 校验 plugin/agent id 并做包含性判定；`api_vcc` 经 `core.scope.normalize_agent_id`。
- models apply/rollback：`confirm` 强制、单 agent 约束、字节级快照、写后回读校验、不一致自动还原、快照目录穿越防护。
- console settings：拒绝掩码值回写、乐观锁、走官方写入器、线程池执行。
- remote 凭据：GET 只返回掩码；reveal 需 POST + `confirm is True` + 白名单 + `no-store`。
- lanes：只读、PID 复用检测、字段白名单。
- `plugin_api` 故障隔离：单域 import 失败只丢自己的路由，`/health` 结构化暴露；`/modules` 坏掉也只 503，不拖垮其它路由。
